## Cross-subsystem co-ownership notes

- **`SessionController.php`** (physical owner `session-view`) also carries feature lines reported under `prompt-interaction` (answer/send/mode/model/escape), `plan-files` (plan/todo), `uploads` (uploaded_*), and `archived-sessions` (showArchived/archived*). Per Andres: report each feature's lines under its subsystem; **no physical split planned**.
- **`public/js/session.js` / `sidebar.js`** (physical owner `session-view`) carry feature blocks reported under `prompt-interaction`, `plan-files`, `uploads`, `archived-sessions` — same reporting rule.
- **`StatuslineMarkerService.php`** (physical owner `session-status-state`) writes a statusline quota-capture block reported under `quota` — no physical split planned.
- **`HealthBoxView` + `health-box/*`** (physical owner `dashboard`) are the view; the backend `PushHealthService::health_check()` is owned by `push-notifications` (#4 decision).
- **`tests/test_sessions_lifecycle.php`** is a shared integration harness spanning lifecycle/listing/archived/search/transcript — not wholly owned by any one subsystem (#5 decision).
- **`SqliteDb`** (physical owner `session-status-state`) is the shared storage dependency for all Stores; **`Config`** (physical owner `host-agent-runtime`) is the shared env/path layer for nearly every host service; **`TmuxService`/`ProcessRunner`/`ProcessInspector`** (physical owner `session-core`) are shared tmux/process primitives.

## Descriptive digest

Prose digest of each subsystem, keyed to its registry row above, reflecting `DETAILS.md` + latest `AUDIT.md` (reference commit `44e4caa`, working tree for the dirty subsystems). Full cross-subsystem synthesis lives in `REPORT.md`.

- **`agent-abstraction`** — The seam that knows which coding-CLI agents exist and what differs at spawn-argv/hook-registration/permission level. Three adapters (`ClaudeCodeAdapter`, `AntigravityAdapter`, `OpenCodeAdapter`) behind `AgentRegistry`. Healthy and narrow, but slightly ahead of its consumers: `check_hooks()`/`install_hooks()`/`permission_mode_map()` have no production caller yet (test-only), and resume argv is inlined in `SessionLifecycleService` instead of routed through the seam. Findings are docblock/wiring and the universal `PageView::AGENT_OPTIONS` hand-mirror drift risk.
- **`archived-sessions`** — Dashboard toggle + per-session browsing of dormant sessions; content search across live + archived. The Claude-Code search core is excellent (two-stage filter, tight snippet builder, correct live/archived link signal). Main defect: the archived **detail** path still resolves transcripts through the Claude-Code-only resolver, so stored Antigravity/OpenCode ids render "Session not found" — the paging/attachment siblings already route through `TranscriptRouter`.
- **`dashboard`** — The home screen: session rows, fragments + take-over flow, search box, health box, index page + JS. Single source of truth for row markup (SSR and poll share `SessionRowView`); re-validate-then-send is real for primary actions; thorough escaping. Key issues: inline `onsubmit` confirm strings break on an apostrophe (confirmation bypass on bare-row kill/take-over); take-over confirm trusts client `workdir`; duplicated agent-badge `match` branching; client take-over/poll branching is HTTP-test-only (no browser-level coverage).
- **`host-agent-runtime`** — The host-native agent frame: `agent.php` entry, two dispatchers, `Config`, systemd + install.sh packaging. Dispatcher/route/action coherence is **verified drift-free** (all 44 controller actions resolve). The two-runtime boundary is structurally sound. Issues: `agent.php` reads the request with no read timeout/size cap; `csm_repo_root()` unquoted in every shell-command builder; `.env.example` documents dead post-SQLite env vars; `json_encode` can return false on invalid UTF-8.
- **`plan-files`** — Read-only sidebar glance at ad-hoc markdown plan/handoff files + the session cwd `todo` file. Genuinely read-only; workdir re-derived from the sidecar, never trusted from the caller; `read_plan_file` is well armored. Gap: `read_todo_file()` does **not** enforce the realpath boundary its own docblock claims (a symlinked `todo` can read outside the workdir), and the todo status→presentation mapping is duplicated PHP/JS.
- **`prompt-interaction`** — Detecting + answering blocked/ask prompts across all agents, send/mode/model/escape, CSM + per-agent vocabulary, and the OpenCode permission bridge. Re-validate-then-send is consistently honored and the single-vs-multi AskUserQuestion carve-out is coherent. Highest-consequence unknown: the multiSelect-as-LAST-question key sequence ships an explicitly-unverified generalization (should reject until confirmed). The PHP `PermissionStore` is an orphaned half-bridge with a latent stale-intent race.
- **`push-notifications`** — Web-push to a phone when a session blocks / task finishes: subscription storage, VAPID delivery, transition detection, timer, sw.js, health backend. Correct edge-triggered state machine and store-level atomicity. Remaining races/fixes: the subscription table prune is a snapshot-replace that can clobber a concurrent subscribe; a transient send failure consumes the transition (notification lost); `sw.js` approve/deny swallows a failed fetch; health "timer may not be running" threshold hardcoded 120s vs interval up to 300s.
- **`quota`** — Reading Claude quota from the statusline marker + Antigravity via `/usage` poll, plus display and push quota state. Read side is well-built (strict `captured_at` validation, no-throw contract). Defects concentrate in the two standalone writer scripts: `antigravity_quota_poll.php` wipes prior good state on a success-but-empty poll; `quota_live_state_write.php` is not atomic despite a docblock claim otherwise. `opencode_quota_state()` can throw past its connect-time guard.
- **`session-core`** — The foundational session domain layer + tmux/process primitives. The single most important risk in the repo: a transient tmux query failure is conflated with "no sessions", so the orphan-prune **irrecoverably wipes** `sidecars`/`session_status`/`pending_tools`. Also: `ProcessRunner` no timeout/sequential-drain deadlock; per-session read amplification; several docblock/`@return` drift items. Two-runtime boundary airtight; proc_open array-form everywhere.
- **`session-lifecycle`** — Create/resume/kill/adopt sessions + new-session folder browse. The resume `flock()` is a genuinely correct TOCTOU fix, not over-engineering. `kill_bare_process()` does not enforce "bare" (can kill a managed session, bypassing cleanup — crafted only); create/resume are ~90% duplicate bodies (the DRY debt the split left); a stale test assertion (`:760`) guards nothing.
- **`session-status-state`** — Hook-fed session status, pending-tool & sidecar state, hook installation, the SQLite/status-file records. The atomic `update_status()` merge is correct where it mattered (column-preserving, `array_key_exists` not `isset`). Critical: **every hook's store write is unguarded** — a store/DB failure crashes the hook out (exit non-zero; Antigravity skips its required `decision`), violating the "always exit 0" contract. Plus a remaining sidecar read-modify-write race, a docblock/impl mismatch in `update_status`, `write_status` dropping `last_turn_error`, and cron-sized preambles duplicated across 9 hooks.
- **`session-view`** — The session detail page: transcript reading/rendering across every backend, history paging, attachments, markdown renderer, session-detail page + JS. The PHP↔JS block-render mirror is genuinely exact and the markdown XSS posture solid. Biggest issue: OpenCode forward-poll misaligns the `line` cursor with the filtered entry array → a live session's page silently stops updating. Secondary: PHP/JS markdown escaping diverge on quotes; the `data-line`/`.copy-btn` invariant isn't enforced for `image` blocks; a malformed docblock in `find_pending_question`.
- **`uploads`** — Compose-bar file uploads into a session's `.claude/uploads/`. Good two-layer path safety for read/delete; a self-healing `.gitignore`; service-level happy+sad coverage excellent. Gaps: the **write** path never goes through the realpath boundary (broken-symlink write-through); invalid-UTF-8 filename breaks the JSON protocol; no client-side size guard (misleading "No file uploaded" over `post_max_size`); controller sad-path branches untested at the HTTP layer.
- **`web-shell`** — Container-side request plumbing + shared page shell: front controller, router, AgentClient socket protocol, auth/CSRF, base Controller/View/PageView, layout shell, static assets, build config. Static passthrough correct and complete; two-layer CSRF sound; portability precedent honored (front controller works behind Apache/nginx too). Highest issue: `AgentClient::agent_call()` has **no read timeout** — a wedged host agent hangs the request (and, under `php -S`, the whole app). `npm run typecheck` is red (134 errors); router can't emit 405 on GET-only wrong-verb routes; CSRF cookie defaults are bare.

### Cross-subsystem synthesis note

This is a healthy, unusually well-documented single-user app whose two-runtime split is structurally correct and verification-safe. The class of defect that matters most is the **silent failure**: the `session-core` orphan-prune wipe, the crash-path hook contract violation, the OpenCode live-view freeze, and the unbounded socket/process reads — all fail quietly rather than surfacing as a handled error. Fix the foundation triad first (`session-core`, `session-status-state`, `host-agent-runtime/web-shell`) before the feature surfaces, and sweep the recurring "realpath boundary reimplemented in 5 places + the write paths that skip it" and "hook preamble duplicated in 9 scripts" into shared helpers to keep the density from turning into drift.

Co-ownership (SessionController + session.js/sidebar.js partitioned across prompt-interaction/plan-files/uploads/archived-sessions; StatuslineMarkerService quota block → quota; HealthBoxView view → dashboard with backend in push-notifications; `test_sessions_lifecycle.php` shared harness; SqliteDb/Config/TmuxService/ProcessRunner/ProcessInspector shared primitives) is confirmed and reflected in the findings above — no physical split is planned, so the same file:line can legitimately appear under multiple subsystems. One attribution/inventory gap to fix: `tests/test_agent_client_protocol.php` (exercises web-shell's `AgentClient`) should be added to web-shell's `owned_paths`, and the untracked `host-agent/systemd/opencode-serve.service` + `host-agent/opencode-plugins/` must be committed before an open-source publish.
